# Функциональные требования к MVP

## 1. Use Case: Отметка выполнения привычки

**Название:** Отметить привычку выполненной за текущий день

**Актор:** Пользователь

**Предусловия:**
- Пользователь открыл приложение
- В системе существует хотя бы одна привычка
- Привычка ещё не отмечена как выполненная за сегодняшний день

**Основной сценарий:**
1. Пользователь переходит на главную страницу (`/`) или страницу списка привычек (`/habits`).
2. Система отображает список привычек с текущим прогрессом.
3. Пользователь нажимает кнопку «Выполнено» (или чекбокс) на карточке нужной привычки.
4. Система увеличивает счётчик выполнений привычки за текущий день.
5. Система обновляет визуальный индикатор прогресса (ProgressBar) и серию (streak).
6. Система показывает подтверждение (изменение состояния кнопки / прогресса).

**Результат:**
- Привычка отмечена как выполненная за сегодня.
- Обновлён прогресс и статистика.
- Изменения сразу отражены в интерфейсе.

**Альтернативные сценарии:**
- **A1.** Привычка уже отмечена сегодня → кнопка неактивна или показывает «Выполнено», повторная отметка невозможна.
- **A2.** Пользователь хочет снять отметку → предусмотрена возможность отменить выполнение (кнопка меняет состояние).

## 2. Границы MVP

### Входит в первую версию (MVP)

- Просмотр списка привычек
- Создание новой привычки (название)
- Удаление привычки
- Отметка выполнения привычки за день
- Отображение текущего прогресса (ProgressBar)
- Подсчёт серии выполнения (streak)
- Сохранение данных в localStorage
- Простая статистика (прогресс за сегодня и средний прогресс)
- Навигация между страницами: Главная, Список привычек, Детали привычки, Статистика
- Адаптивный интерфейс
- Использование переиспользуемых компонентов из библиотеки `ui`

### Не входит в MVP (будущие версии)

- Авторизация и несколько пользователей
- Хранение данных на сервере (сейчас — localStorage)
- Уведомления (push / email)
- Тёмная тема
- Категории и теги привычек
- Иконки и кастомизация внешнего вида привычек
- Экспорт / импорт данных
- Графики за произвольный период
- Социальные функции (друзья, рейтинги)
- Мобильное приложение (PWA можно добавить позже)

## 3. Критерии готовности MVP

- Все маршруты из `architecture.md` существуют и открываются без ошибок.
- Компоненты библиотеки `ui` реально импортируются и отображаются в приложении.
- Пользователь может отметить привычку выполненной и увидеть изменение прогресса.
- Скрипты `dev`, `build`, `lint`, `test` проходят без ошибок.
- Покрытие тестами хотя бы одного компонента библиотеки ≥ 70%.
